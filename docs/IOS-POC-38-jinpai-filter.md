## 二、根因

### 2.1 腳本：電影多了一列後端不理會的「類型」

網站自己的前端（`zjuys.com` 轉址到 `www.hellorlgzf7sn.com`，`/vod/show/id/1` 頁的 `page-d27aa074b6038ebd.js`，2026-09-29 取得）定義篩選列時寫著：

```js
for (let i of g) ("1" !== t || "typeList" !== i.value) && e[i.value] && (r.push(i), a.push(e[i.value]))
```

分類 id 是 `"1"`（電影）時跳過 `typeList`——**網站本身對電影不顯示「類型」**，電影的類型要用「劇情」篩。腳本的 `homeContent` 對每個分類都組出「類型」列，所以 App 在電影下多了一列選了沒作用的篩選。

同一段程式也顯示網站會在**每一列最前面自己加「全部」**（`[{label:"全部",value:"all"}, ...e]`）；腳本沒有加。

### 2.2 App：已選的篩選無法取消

`ios/WebHTVApp/Sources/WebHTVApp.swift` 的 `filterChip` 以空值代表「全部」，點一個選項就設定該值，**再點同一個選項仍是設定同一個值**。來源的每一列都沒有空值選項時（金牌系列就是），選過之後就沒有辦法回到不限，只能換分類。

Android（本 repo `app/src/main/java/com/fongmi/android/tv/bean/Value.java` 的 `setSelected(Value)`：已選且相同 → 取消；`TypeFragment.setFilter`：取消時從 extend 移除該 key）是**再點一次就取消**。iOS 少了這個行為。

## 三、App 端修正（本 repo）

`filterChip`：點到的是空值、或是目前已選的那個值時，移除該列；否則設定該值。與 Android 相同，對有「全部」的來源行為不變（點「全部」仍是移除）。

## 四、腳本端 patch（使用者的 GitLab `recha`，本 repo 不含）

套在 `py/又是一個金牌.py`（上面那個 SHA-256 的版本）：`docs/IOS-POC-38-jinpai-filter.patch`（unified diff，`patch -p1` 或 `git apply`）。內容兩段：

- 第一段：電影不再出現「類型」列（與網站相同）。
- 第二段：每列加「全部」，並拿掉沒有選項的列（短劇的「地區」「語言」目前是空列）。有了第三節的 App 修正，第二段不是必要，但畫面會與網站一致。

## 七、IOS-POC-38.1 — 空狀態提示蓋住篩選列（2026-09-30）

使用者回報：「篩選地區 年份 語言不支援」。

### 7.1 不是後端

host 上對 zjuys 每個分類的地區／年份／語言逐一測試，**全部都有過濾**（例：綜藝＋港台綜藝＋地區中国台湾 → 10 部全是台灣；＋英语 → 1 部；電視劇＋港台劇＋中国台湾 → 30/30 台灣）。例外只有：短劇的「地區」「語言」網站本身沒有選項；電視劇、動漫選 2026 與不篩選相同（最新的本來就是 2026）。有些組合合理地回 **0 筆**，例如「港台綜藝」＋「地區：中國大陸」。

### 7.2 根因（App）

`CMSView` 的「載入中／載入失敗／沒有內容」是 `.overlay` 置中蓋在整個畫面上。有篩選列時，畫面中央正是「年份／語言／排序」幾列，所以組合一回 0 筆，「沒有內容」的圖示與文字就畫在那幾列上，**並攔截點擊**。模擬器重現（修正前）：綜藝 → 港台綜藝 → 中國大陸 → 「沒有內容」壓在語言、排序列上 → 點「粵語」沒有反應。使用者看到的就是「這些篩選不支援」。

選「港台綜藝」後清單晚幾秒才換，是網路延遲，不是競態：spider session 有快取（`SpiderSessionStore`），同一站的呼叫在自己的序列佇列上依序執行。

### 7.3 修法

- 有分類列時，三種提示改放在篩選列**下方**、原本影片格的位置（`emptyState.padding(.top, 48)`）。
- 沒有分類列時（剛進來源的第一次載入、或來源沒有分類）維持原本的置中 overlay。
- 提示的內容與優先順序不變（載入中 > 載入失敗 > 沒有內容）。
