### 2.4.1 關鍵字被改寫（「哪吒」搜了兩次）

## 3. 發現的問題（依影響排序）

1. **相關的作品被淹沒**：一次搜尋有 492–1,220 筆結果，「全部」只依站台回應先後攤平。最先回應的往往是 YouTube（解說、精華）或做模糊比對的站，真正要找的正片常不在第一頁（§2.5）。
2. **同系列各季打散、順序亂**（使用者需求 ②）：怪奇物語同一站的各季順序是 4、5、3、1、2；慶餘年第二季排在第一季前；跨站時同一季分散在好幾百張卡之間。
3. **大量重複**：同一部作品在十幾個站都有（§2.4），每個站各占一張卡。
4. **雜訊站**：短劇聚合、圍觀短劇、bili 聽書／漫畫／歌曲每次都回 20–59 筆和關鍵字無關的結果，App 裡沒有辦法讓它們不參與搜尋（FongMi 有每站開關）。
5. **固定失敗的站白佔名額**：每次都有同一批 8–10 個站失敗（CMS 站被擋、缺模組的 Python 站），其中采集集合、愛瓜每次要等 10–20 s 才失敗，而且照設定檔順序排在前面，佔掉 6 個名額中的一部分。搜尋沒有使用已有的站點健康分數（`SiteHealth.ordered` 只用在換站清單）。
6. **全部完成要 19–39 s**：第一筆結果很快（0.4–1.5 s），但一半的結果要 7–15 s、全部要 19–39 s；同時搜尋上限 6 是主因之一（§2.3）。
7. **沒有搜尋紀錄、建議詞**：每次都要重打；中文輸入在手機上成本高。
8. **部分簡體關鍵字被改寫後多搜一次**（§2.4.1）：含吒、呼、猛、糊、溜、劈等 14 個字（§2.4.1 表）的簡體關鍵字，每個站要搜兩次，第一次用的是錯字。Android 行為相同（同一張表）。

## 4. 系列拆名與歸組設計

### 4.1 共用元件（Core，W-312 與 W-313 共用）

新檔 `ios/Sources/WebHTVCore/SeriesTitle.swift`，純函式、不碰網路，可完整單元測試：

```swift
public struct SeriesTitle: Hashable, Sendable {
    public enum Strength: Sendable { case none, weak, strong }
    public enum Special: Sendable { case movie, special, extra }   // 劇場版/電影版；特別篇/SP/OVA/總集篇；番外
    public let original: String
    public let baseKey: String       // 比對用（見 4.2 第 1 步），不顯示
    public let baseDisplay: String   // 原文去掉季數與特別篇標記，給搜尋新季當關鍵字（W-313）
    public let season: Int?          // nil = 沒有標記；排序時當第 1 季
    public let strength: Strength
    public let special: Special?
    public let tags: [String]        // 尾端括號標籤：(2019)、[國語]、4K…
    public init(_ title: String)
}

public enum SeriesGrouping {
    /// 保守歸組：baseKey 完全相同，且組內至少一個成員有季數標記（strong 或 weak），才併成一組；組內依季數升冪、特別篇殿後。
    public static func groups<T>(_ items: [T], title: (T) -> String) -> [[T]]
    /// W-313 新季判斷（定案）：同 baseKey、candidate.strength == .strong、candidate.special == nil、
    /// candidate.season > (watched.season ?? 1)。weak（「慶餘年2」）與沒有標記的候選一律回 false。
    public static func isNewerSeason(_ candidate: SeriesTitle, than watched: SeriesTitle) -> Bool
}
```

### 4.2 拆名規則（依序）

1. **折疊**：Unicode NFKC（全形轉半形，`：`→`:`）→ 繁轉簡（沿用 `TraditionalSimplified.toSimplified`，和送出搜尋的是同一張表）→ 小寫。
2. **尾端標籤**：反覆剝掉尾端的括號段 `(…)`、`[…]`、`（…）`、`【…】`（12 字以內），放進 `tags`，不算進基名。年份就在這裡，所以「射鵰英雄傳(2017)」「射鵰英雄傳(1983)」基名相同，但都**沒有季數標記**，依第 5 步不會被併成一組。
3. **特別篇**：尾端是「劇場版／電影版／特別篇／番外（篇）／總集篇／SP／OVA」時記成 `special`，剝掉後再往下看；季數後面才接特別篇的（「慶餘年第一季特別篇」）也照樣拆得出季數 1。
4. **季數標記**（只看尾端，前面可以有空白、冒號、間隔號、破折號）：
   - **strong**：`第N季`、`第N部`、`第N輯`（N 為阿拉伯數字或中文數字，含「十」「二十一」「兩」）；`Season N`；`S N`／`S0N`。
   - **weak**：片名最後直接接 2–20 的阿拉伯數字，而且前一個字是中文（「慶餘年2」「唐人街探案3」「暴走財神3」）。1 不算（「XX1」多半是誤判）；前一個字不是中文的不算（「1917」「2046」「007：無暇赴死」整個保留）。
   - 沒有以上標記：`strength = .none`、`season = nil`。
5. **基名鍵**：剩下的字去掉空白與標點（`: · - — _ ~ ! ? , . 、 《》「」『』` 和引號），就是 `baseKey`；`baseDisplay` 是原文去掉同一段標記後的樣子（不折疊、不轉簡）。

### 4.3 歸組與排序（搜尋結果的「全部」）

1. 以 `baseKey` 分桶。桶裡**至少一個**成員有季數標記，而且季數或特別篇至少有兩種不同值，才成為一個「系列組」；否則每個成員各自獨立（重拍版、同名不同片不會被併）。
2. 組內排序：正季依季數升冪（沒標記的當第 1 季），同季依相關度、再依站台順序；特別篇／劇場版排在正季之後。
3. 組與組之間、組與單片之間依相關度排序（§5 的 A1）；一個組的相關度取組內最高者，整組放在那個位置。
4. 同一季在多個站都有時，依 §5 的 A3 合併成一張卡；沒做 A3 時就同季相鄰。
5. **結果陸續到達時不讓卡片在手指底下跳動**（A1、A2、A3 共用）：結果會在 19–39 秒內陸續到達（§2.2），每到一站就重排的話，使用者正在看或正要點的卡會移位。規則：
   - **還沒互動前**：使用者還沒捲動、也還沒點任何卡時，每到一站就重排，畫面頂端永遠是目前最相關的。
   - **一旦互動就凍結**：使用者第一次捲動結果、點卡片、點晶片，或從詳情頁返回時，「全部」的順序立刻凍結。之後到達的結果不插進已顯示的列表，只累計成畫面頂端的提示列「有 N 筆新結果，點這裡重新排序」；點了才重排並捲回頂端。
   - **搜尋結束**：全部站台回應完時，如果還沒凍結，就做最後一次排序；已凍結的維持原樣，提示列保留。
   - 單站晶片不受影響（它本來就照該站回傳順序，只會在尾端加「載入更多」的內容）。
   - 實作上把「顯示用的順序」存成一個 `[Hit.ID]` 快照，凍結後新到的 hit 放進 pending 集合；不需要動 `AggregateSearch`。

### 4.4 誤判風險與保守規則

| 情況 | 例子 | 規則下的結果 |
|---|---|---|
| 片名本身以數字結尾 | 1917、2046、長安十二時辰 | 不拆（前字不是中文、或不是阿拉伯數字） |
| 同名重拍 | 射鵰英雄傳(1983)／(2017) | 年份在標籤裡，兩部都沒季數，不併組 |
| 續集改了副標題 | 鬼滅之刃 無限列車篇／遊郭篇 | 基名不同，不併組（漏併，但不會錯併） |
| 季數後面還有分段 | 進擊的巨人 第三季 Part.2 | 第一版不拆（整個當基名，獨立一張卡）；`Part N` 列為第二版規則 |
| 解說／預告也帶片名 | 慶餘年 第二季[預告片]、慶餘年[電影解說] | 標籤剝掉後會進同一組。靠 A1 相關度＋A2 把 YouTube／解說類站台的結果排後面；要完全排除需看 `type_name`（第二版） |
| 數字其實是集數 | 「XX 12」 | 只認 2–20、而且前字是中文才算 weak；weak 只用來排序，新季通知只採 strong（4.5 約定） |
| 短劇同名不同劇 | 不同短劇站的同名作品 | 只會相鄰，不會錯誤合併成一張卡（A3 另外要求年份或集數也相符） |

### 4.5 給 W-313 的約定

- 新季偵測拿 `baseDisplay` 當搜尋關鍵字（繁簡由 `DualScriptSearch` 處理），用 `isNewerSeason` 判斷候選。
- **約定**：新季只認 `strength == .strong` 的候選（§4.1 `isNewerSeason` 的條件，W-312 與 W-313 都以這裡為準）。weak（「XX2」）只用在搜尋結果的歸組排序（§4.3），不觸發通知：「XX2」也可能是集數或同名不同作，通知誤報的代價比排序錯位高。要放寬時改這一處並同步兩份文件與 `SeriesTitleTests`。
- 規則有改時兩邊共用同一份測試資料（`SeriesTitleTests` 的片名表），不各自維護。

## 7. 驗收條件（建議方案第一批）

0. `TraditionalSimplifiedTests`：§2.4.1 表中排除的 14 個字原樣保留，`DualScriptSearch.forms("哪吒")`、`forms("猛龍過江")` 只有一種寫法；反例照舊有兩種寫法：`forms("合夥人") == ["合伙人", "合夥人"]`、`forms("活著") == ["活着", "活著"]`、`forms("鍾馗") == ["锺馗", "鍾馗"]`；既有繁轉簡案例（含「慶餘年」）不變。Simulator 搜「哪吒」日誌沒有 `form 1/2`。
1. `SeriesTitleTests`：§4.4 表格的每個例子，加上 §2.4 實測片名中抽出的歸組結果，全部符合預期；`1917`、`2046`、重拍版不被併組。
