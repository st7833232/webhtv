- 其他證據類別：XBPQ 是閉源，**沒有官方規格、上游 PR／issue 或 maintainer 討論**可查；成熟相關專案（其他 TVBox 分支的 XBPQ 規則教學）這次沒有查，因為反編譯原始碼已能決定本階段的設計。

### 4.1 規則怎麼讀進來（`init`、`F`）

- `init(ext)`：`http` 開頭且不含 `{cateId}` → 下載後以 Android `org.json` 解析（`JSONTokener` 本來就略過 `//`、`/* */`、`#` 註解）；`http` 開頭且含 `{cateId}` → 整串就是 `{"分类url": ext}`；`{` 開頭 → JSON；其他 → `鍵:值,鍵:值`（`\,` 是逗號跳脫）。**iOS 缺第一、二、四種。**
- 取值 `F(key, default)`：值是空字串或 `空` → 用預設（`搜索后缀` 的 `空` 例外，表示真的空）；值含 `||` 與 `--` 時依目前情境（首頁／搜尋／分類名）選一段。多數鍵有別名鏈，由 `G/H/I/J/K` 依序取第一個有值的，例：`主页url` ← `首页推荐链接` ← `网站地址` ← `url` ← `homeUrl` ← 由 `分类url`／`分类链接`／`分类页`／`class_url`／`cateUrl`／`搜索url` 取網域。
- 旗標：`分类url`（沒有就看 `搜索url`）以 `;;` 切開，後段是旗標字串 `s`。確認語意的：`z` ＝ 直接播放、`D` ＝ 短視頻、`d`（非 `d0`）＝ 倒序、`h`/`h1`/`h2` ＝ 橫圖、`t` ＝ 圖片代理、`T` ＝ 除錯、`u0` ＝ 跳轉網址不做 URL decode、`o<n>` ＝ 重試次數、`!` ＝ 自動分類排除福利、`域<n>` ＝ 從發布頁取第 n 個網域。其餘（`y`/`Y`/`r`/`R`/`c`/`c0`/`L`/`J`/`Jb`/`g`/`x`/`W`/`C`/`m`/`k0`）未研究。本批：`;;z` 45 站、`;;mrcd0` 2 站、`;;zm` 1 站、`;;`（空）1 站。

|---|---|---|---:|
| `前&&後` | 取所有「前…後」之間的字串（非貪婪） | 有 | — |
| `&&後`／`前&&` | 從頭截／截到結尾 | 部分（空的前綴從頭找） | 1 |
| `*` | 前綴裡的萬用字元，比對 `([^>]*?)`（不跨 `>`），取最後一個群組 | **無** | 38 |
| `**` | 萬用字元，比對 `([\S\s]*?)` | **無** | 0 |
| `A+B+C` | 各段分別取值後串接；**沒有 `&&` 的段是字面文字**（例 `🌹+alt="&&"`）；某段結果以 `http` 開頭時前面清空；`url:` 段是另外抓一頁 | **無** | 10 |
| `\+` `\(` `\)` `\&` `\#` | 跳脫 | **無** | 2 |

### 4.3 分類（`homeContent` → `m()`）

1. `分类` 含 `$`：`名$id#名$id` 直接用。
2. `分类` 含 `&`：與 `分类值` 以 `&` 逐一配對（`T()`，`分类值` 是 `*` 或空時 id ＝ 名稱）；別名 `分类名称`＋`分类名称替换词`、`class_name`＋`class_value`。本批 3 站。
3. `分类数组` 含 `&&`（不以 `//` 開頭）：抓 `主页url`，先套 `分类二次截取`，以 `分类数组` cut 出每一塊；名稱 ＝ `分类标题`（預設 `>&&</a>`，對「塊＋`</a>`」取），去掉 entity 與標籤；id ＝ `分类ID`（別名 `分类链接`、`cateId`，預設 `href="&&"`）。本批 24 站用 `分类数组`、24 站用 `分类ID`。
4. 都沒有：以 XPath 自動找導覽列（`//ul[contains(text(),'电影')…]//a[not(…)]`，再從連結推 id），失敗時用 `电影$1#连续剧$2#综艺$3#动漫$4`。
5. 繁體分類名轉簡體（電影→电影…）。`列表分类`／`fenlei` 若有則覆蓋。

| 沒有規則 | 2 | 风流、夜夜新郎：`ext` 指到外部網址，這次沒抓 |

結論：原版語意能讓 iOS 目前 0 部的站取到片（至少 4 站在公司網路上已證實），但「最後能用幾站」受網站本身（JS 跳轉頁、網域失效）與網路限制，**現在定不出站數目標**，要在熱點下分階段量。

### 4.7 iOS `XBPQ.js` 與原版的差距（依影響排序）

1. `init` 不下載 `http` ext（41 站規則是空的）。
2. `分类url` 的 `;;旗標` 沒切掉（45 站請求錯網址）。
3. 列表規則鍵用錯：用 `分类数组`／`分类标题`／`分类链接`／`分类图片` 當影片列表（原版這些是抓分類用的），原版的 `数组`／`标题`／`图片`／`链接`／`副标题` 與預設值完全沒實作。
4. cut 缺 `*`、`+`、跳脫，`[包含]`／`[不包含]`／`[替换]` 的 `#` 多值。
5. 分類缺 `分类`＋`分类值`、`分类数组`＋`分类标题`＋`分类ID`。
6. 網址缺 `起始页`、`[firstPage]`、沒填的 `{x}` 與 `/x/` 刪除、`//` 收斂；搜尋缺 `{pg}`／`{catePg}`。
7. 詳情缺 `播放数组`／`播放列表`／`播放标题`／`播放链接`、`直接播放`；播放缺 `跳转播放链接`（及多層）、`免嗅=0`、`嗅探词`。

## 5. 方案、驗收與回滾（待核准）

### 5.1 選項比較

| 選項 | 內容 | 評估 |
|---|---|---|
| A. 不改 | 維持現狀 | 104 站維持不可用。不建議 |
| B. 原版照搬 | 連 XPath 模式、自動分類、OCR／驗證碼、寶塔盾、`浏览器` WebView、阿里雲盤、多頁合併、所有旗標一起移植 | 四個核心方法只能從原始指令推讀（合計約 3 萬條），OCR 與 WebView 需要新的原生能力（`host.js` ABI 變更、不能用相容性套件出），本批站幾乎沒用到。不建議 |
| **C. WebHTV 窄版（建議）** | 只實作本批站實際用到的鍵與語法（第 4.7 節 1～7），全部寫在 `XBPQ.js` 內，自帶 cut（不改 `host.cut`／`host.js`） | 改動集中在一個可被相容性套件替換的腳本，之後 jar 更新可以用套件出，不必發版；`host.js` 與其他 spider 不受影響 |

C 的具體取捨：
- **保留現有的蘋果 CMS DOM 預設（`defaultList`）**：沒有 `数组` 時先跑它（紅果短剧就是靠它可用），它回 0 才試原版自動模式的三種 cut。
- **`vod_id` 維持「絕對連結」**，不改成原版的 `片名$$$圖片$$$連結`：觀看記錄與搜尋合併都以 `vod_id` 為 key，改格式會讓既有 XBPQ 記錄對不上。直接播放改由 detail 讀 rule 判斷（同一個 session 內 rule 已在），片名改從詳情頁取（多一個請求）。偏離原版，列為已知差異。
- 不做：XPath 模式、自動分類（4.3 第 4 種，8 站）、OCR／驗證碼、寶塔盾、WebView、阿里、未研究的旗標、`编码` 非 UTF-8（1 站）、多頁合併。之後有需要再開階段。

### 5.2 分階段（每階段一個 commit、可獨立回滾）

| 階段 | 內容 | 對應差距 | 預計 |
|---|---|---|---|
| **S1 規則與網址** | `init` 下載 `http` ext、`{cateId}` 網址、`鍵:值` 格式；`;;旗標`（`z`）；`F` 的 `空` 與別名鏈；分類網址 `f`/`N`（`起始页`、`[firstPage]`、刪未填 `{x}` 與 `/x/`、`//` 收斂）；分類 `分类`＋`分类值`、`分类数组`＋`分类标题`＋`分类ID`＋`分类二次截取` | 1、2、5、6 | 約 1 小時 |

| **S3 列表** | `二次截取`／`列表二次截取`、`数组`、`标题`、`图片`、`链接`（前後綴）、`副标题` 與預設值；分類鍵不再當列表鍵；`defaultList` → 原版自動模式；`首页` | 3 | 約 1 小時 |
| **S4 詳情與播放** | `播放数组`／`播放列表`／`播放标题`／`播放链接`（前後綴、`播放二次截取`）、`线路*`、`直接播放`、`倒序`；`跳转播放链接`（＋二～五次）、`免嗅`、`嗅探词`／`过滤词` | 7 | 約 1.5 小時 |

S1～S3 決定「有沒有片單」，S4 決定「能不能播」（sweep 的「可用」要讀到影片位元組，所以要到 S4 才會看到可用數上升）。

### 5.3 驗收標準

1. **不退步（硬性）**：`docs/SITE-AVAILABILITY-2026-09-30.md` 中兩份設定檔原本「可用」的站，每階段後都仍可用；XBPQ 中唯一可用的紅果短剧（`wang-movie.json`）必須可用。sweep 顯示變不可用的站，要以 curl 證明是網站本身的變化才算通過。
2. **單元測試**：`swift test --package-path ios` 全過（含 `SpiderHostTests.slicesTextTheWayXBPQRulesDo`，`host.cut` 不動所以應不變）；新增以本批真實規則與存下來的 HTML 片段為輸入的 XBPQ 測試，每一條 4.2 的語法至少一例（`*`、`+`、`#` 多值、`>>空`）、`;;z`、`http` ext、`分类`＋`分类值`、`分类数组` 分類、`数组` 列表、`跳转播放链接`。
3. **改善（量測，不設死門檻）**：在**個人熱點**下跑 `SWEEP_CONFIG=wang-sex.json` 的 sweep。S3 後，「首頁或第一個分類有片」的 XBPQ 站從 0 提高，4.6 在公司網路已取到片的 18j、文件夹、一区、天美 4 站必須有片；S4 後回報「可用」站數與每一站不可用的原因分類（網站 JS 跳轉頁、網域失效、未實作的鍵、其他）。最後站數以熱點下的實測為準，並寫回 `SITE-AVAILABILITY` 文件。
4. 真機：模擬器或真機沒測到的一律寫「未驗證」。

### 5.4 回滾

- 所有程式變更只在 `ios/Sources/WebHTVCore/Resources/Spiders/XBPQ.js` 與新增的測試；`host.js`、Swift、其他 spider 不動。每個階段一個 commit，`git revert <commit>` 即回到上一階段。
- 已發布的 App 若出問題：`XBPQ.js` 可被相容性套件（`./spiders/manifest.json`）覆蓋，可以用套件把舊版 `XBPQ.js` 推回去，不必等發版（需使用者把檔案放到 `recha`）。

### 5.5 風險與未決

- **16 站用的是別的 jar**：`wang-sex.json` 的 XBPQ 站有 90 站指 `xyqxbpq.jar`、10 站指 `./jar/XBPQ.jar`、6 站指 `https://raw.githubusercontent.com/aliluya1977/TVBox/master/spider.jar`，後兩個這次沒抓、沒比對，語意可能不同。
- 約 15 站的網站回傳 JS 跳轉頁，原版同樣不執行 JS，Android 上是否可用未確認；約 40 站在公司網路 DNS 解析失敗，需熱點重測。
- `A()`／`Z()`／`detailContent`／`playerContent` 的流程是從原始指令推讀，可能有細節偏差；以真實站的 sweep 與單元測試兜底。
- `vod_id` 不採原版格式（5.1），直接播放的片名要多抓一次詳情頁。
