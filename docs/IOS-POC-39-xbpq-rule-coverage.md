### 4.1 規則怎麼讀進來（`init`、`F`）

- `init(ext)`：`http` 開頭且不含 `{cateId}` → 下載後以 Android `org.json` 解析（`JSONTokener` 本來就略過 `//`、`/* */`、`#` 註解）；`http` 開頭且含 `{cateId}` → 整串就是 `{"分类url": ext}`；`{` 開頭 → JSON；其他 → `鍵:值,鍵:值`（`\,` 是逗號跳脫）。**iOS 缺第一、二、四種。**
- 取值 `F(key, default)`：值是空字串或 `空` → 用預設（`搜索后缀` 的 `空` 例外，表示真的空）；值含 `||` 與 `--` 時依目前情境（首頁／搜尋／分類名）選一段。多數鍵有別名鏈，由 `G/H/I/J/K` 依序取第一個有值的，例：`主页url` ← `首页推荐链接` ← `网站地址` ← `url` ← `homeUrl` ← 由 `分类url`／`分类链接`／`分类页`／`class_url`／`cateUrl`／`搜索url` 取網域。
- 旗標：`分类url`（沒有就看 `搜索url`）以 `;;` 切開，後段是旗標字串 `s`。確認語意的：`z` ＝ 直接播放、`D` ＝ 短視頻、`d`（非 `d0`）＝ 倒序、`h`/`h1`/`h2` ＝ 橫圖、`t` ＝ 圖片代理、`T` ＝ 除錯、`u0` ＝ 跳轉網址不做 URL decode、`o<n>` ＝ 重試次數、`!` ＝ 自動分類排除福利、`域<n>` ＝ 從發布頁取第 n 個網域。其餘（`y`/`Y`/`r`/`R`/`c`/`c0`/`L`/`J`/`Jb`/`g`/`x`/`W`/`C`/`m`/`k0`）未研究。本批：`;;z` 45 站、`;;mrcd0` 2 站、`;;zm` 1 站、`;;`（空）1 站。

### 4.3 分類（`homeContent` → `m()`）

1. `分类` 含 `$`：`名$id#名$id` 直接用。
2. `分类` 含 `&`：與 `分类值` 以 `&` 逐一配對（`T()`，`分类值` 是 `*` 或空時 id ＝ 名稱）；別名 `分类名称`＋`分类名称替换词`、`class_name`＋`class_value`。本批 3 站。
3. `分类数组` 含 `&&`（不以 `//` 開頭）：抓 `主页url`，先套 `分类二次截取`，以 `分类数组` cut 出每一塊；名稱 ＝ `分类标题`（預設 `>&&</a>`，對「塊＋`</a>`」取），去掉 entity 與標籤；id ＝ `分类ID`（別名 `分类链接`、`cateId`，預設 `href="&&"`）。本批 24 站用 `分类数组`、24 站用 `分类ID`。

5. 繁體分類名轉簡體（電影→电影…）。`列表分类`／`fenlei` 若有則覆蓋。

- 播放：`解析`／`playUrl` 前綴 → id 本身是影片就直接播 → 抓頁（遇 `检测中`／`跳转中`／`btwaf` 走寶塔盾）→ `免嗅`（別名 `mac`／`Anal_MacPlayer`，**預設 `1`**：解析 `player_*` JSON 的 `url`，含 encrypt 1/2）→ `跳转播放链接`（別名 `播放链接二次截取`，cut 規則，本批最常見 `var player_*"url":"&&"`，需要 `*`）→ `二次`～`五次跳转播放链接` 逐層再抓 → 仍不是影片就交給嗅探（`parse=1`）。`嗅探词`／`过滤词` 決定 `isVideoFormat`（預設 `m3u8#.mp4#.flv#.mp3#.m4a#magnet:#…` 與 `url=http#;post;#.js`）。
- 搜尋 `Z()`：`搜索url`（`K`：`搜索url`／`搜索链接`／`搜索前`／`sousuoqian`／`search_url`／`searchUrl`），`{wd}`、`{pg}`（本批 44 站用 `{pg}`，iOS 只認 `{SearchPg}`／`{searchPg}`）、`{catePg}`。~~沒有 `搜索后缀` 或 `搜索模式`＝某值時，退回「在首頁與分類頁以關鍵字篩片名」~~（2026-10-02 讀完 `Z()` 與 `searchContent` 後更正：首頁／分類篩片名是前面每一步都沒有結果時一律會走的最後 fallback，與 `搜索模式`／`搜索后缀` 無關）。`搜索模式` 的完整語意見第 7.4 節。

### 4.7 iOS `XBPQ.js` 與原版的差距（依影響排序）

1. `init` 不下載 `http` ext（41 站規則是空的）。
2. `分类url` 的 `;;旗標` 沒切掉（45 站請求錯網址）。
3. 列表規則鍵用錯：用 `分类数组`／`分类标题`／`分类链接`／`分类图片` 當影片列表（原版這些是抓分類用的），原版的 `数组`／`标题`／`图片`／`链接`／`副标题` 與預設值完全沒實作。
4. cut 缺 `*`、`+`、跳脫，`[包含]`／`[不包含]`／`[替换]` 的 `#` 多值。
5. 分類缺 `分类`＋`分类值`、`分类数组`＋`分类标题`＋`分类ID`。

### 7.4 原版的搜尋流程與 `搜索模式` 語意（`xyqxbpq.jar`）

`searchContent(key, quick)`：

1. 第一次呼叫 `Z("", key)`（一般搜尋）。
2. **重試條件**＝`搜索模式` 是 `0`，或（`搜索后缀` 有值且 `搜索模式` 不是 `1`），或（搜尋網址含 `/ajax/` 且 `搜索模式` 不是 `1`）。第一次沒有結果又符合重試條件時，把規則的 `搜索模式` **永久改成 `1`**、`搜索模式0` 暫設 `0`，再呼叫一次 `Z("", key)`，之後把 `搜索模式0` 清空。
3. 有結果且 `特殊分类` 不含 `#http` → 回傳。
4. `特殊分类` 裡每個 `http…` 網址各呼叫 `Z(網址, key)`，結果合併；有就回傳。
5. 旗標拿掉 `k0`，呼叫 `Z(主页url + "/;;搜首页", key)`：用列表規則讀首頁、以片名篩；有就回傳。
6. 依分類順序呼叫 `Z(分類第 1 頁網址 + ";;搜首页", key)`，找到第一個有結果的分類就停，沒有結果的分類之間 `sleep` 1 秒。
7. 全部沒有結果 → 回空字串。

`Z(網址, key, quick)`：

1. **網址**：沒有指定網址時取 `搜索url`／`搜索链接`／`搜索前`／`sousuoqian`／`search_url`／`searchUrl` 第一個有值的（`;;` 之前）。不是 `http` 或 `/` 開頭，或含 `&&` 而沒有 `$sub:`（也就是 cut 規則）時，當作沒有網址。`POST请求数据`（`sea_PtBody`）有值時接成 `網址;資料`，之後以 POST 送出。相對路徑補主機。
2. **沒有網址**（而且不是模式 0）→ 抓首頁找 `<form action>`：`method=post` 時是 `action;post;`；action 以 `/` 結尾時是 `action + 第一個 input 的 name + "/{wd}/"`；否則加上 `?` 或 `&` 與 `第一個 input name={wd}`。
3. **頁碼**：`{pgN}` 表示從第 N 頁開始；關鍵字可以帶 `PG<頁>`。頁碼字串 1 位 → 只抓那一頁；2 位 → 從那頁起最多 10 頁；預設第 1～11 頁。
4. **網址組法**：有 `{wd}` 就代入；沒有 `{wd}`（也不是 `搜首页`）時是 `網址 + 關鍵字 + 搜索后`（鍵名是 `搜索后`／`sousuohou`，不是 `搜索后缀`）。
5. **模式判斷**：走模式 0 的條件＝`搜索模式0` 不是 `0`，而且（`搜索模式` 是 `0`，或 `搜索后缀` 有值且 `搜索模式` 不是 `1`，或網址含 `/ajax/` 且 `搜索模式` 不是 `1`）；沒有網址時也直接走模式 0。其餘走模式 1。
6. **模式 1（HTML）**：沒有 `搜索数组` 時把 `網址##關鍵字` 交給列表的 `e()`／`A()`；有 `搜索数组` 時用 `搜索二次截取`／`搜索数组`／`搜索标题`／`搜索链接`／`搜索图片`／`搜索副标题`（另有 `…后` 後綴鍵、`搜索链接前缀`／`后缀`、`跳转搜索图片`）。網址有 `{pg}` 時兩條路徑都會從起始頁往後連抓到上限頁：沒有 `搜索数组` 的路徑在某頁 3 筆以下時停（旗標 `S<n>` 可限制累計筆數），有 `搜索数组` 的路徑停止條件沒有逐條讀。**兩條路徑都丟掉片名不含關鍵字的結果**，除非旗標有 `k0`（那時保留全部、片名後面加 `〔關鍵字〕`）。`搜首页` 時不論有沒有結果都直接回傳。沒有結果且 `搜索模式0` 不是 `0` → `sleep` 1 秒後轉模式 0。
7. **模式 0（JSON）**：網址含 `/ajax/` 就用它，否則打 `主機 + /index.php/ajax/suggest?mid=1&wd=關鍵字&limit=500`（蘋果 CMS 的搜尋建議 API）。回應不是 `{…}` 就沒有結果。`list`（或 `搜索数组` 指定的鍵）的每一筆：片名 `搜索标题`／`jsname`／`jsonname`（預設 `name`，退 `vod_name`）、id `搜索链接`／`jsid`／`jsonid`（預設 `id`，退 `vod_id`、`vod_link`）、圖 `搜索图片`／`jspic`／`jsonpic`（預設 `pic`，退 `vod_pic`）；`quick` 時片名要含關鍵字。詳情連結（這一段暫存器搬移多，**中可信**）：`列表分类` 有值時取 `搜索链接后缀`（別名 `搜索连接后缀`）當 id 前的字串；否則 `搜索链接前缀` 有值時這個字串留空、沒有時取 `搜索后缀`（色花堂的 `/vodplay/` 就是這個用途：名稱叫後綴，實際是 id 前的路徑）；字串是空的就抓第一個分類的列表，從第 2 部的連結切到 `id-`／`id_`／`detail-`／`detail_`／`show-`／`show_` 或最後一個 `/` 當前綴；連結＝字串＋id，之後若 `搜索链接前缀` 有值且連結不是 `http` 開頭，再組成 `搜索链接前缀＋連結＋搜索链接后缀`，否則 `連結＋搜索链接后缀`（`搜索前` 有值時不接後綴）。
8. **xml 模式**：仍沒有結果且 `xml模式` 不是 `0` → `sleep` 1 秒，打 `主機 + /rss.xml?wd=關鍵字`，讀 `<item>` 的 `<title>`／`<link>`／`<pic>`（`<pubDate>` 當備註）；這次也沒有就把規則的 `xml模式` 設成 `0`，之後不再試。

`搜索模式` 每個值實際控制的事：

| 值 | 語意 |
|---|---|
| 沒設、空、`0` 與 `1` 以外的值 | 預設：模式 1（HTML）先，沒有結果才依序模式 0（suggest JSON）→ xml → `特殊分类` → 首頁 → 分類。例外：站台有 `搜索后缀` 或網址含 `/ajax/` 時改成模式 0 先，沒有結果時 `searchContent` 把 `搜索模式` 永久改成 `1` 再重試一次（只走模式 1） |
| `1` | 一律模式 1 先（即使有 `搜索后缀` 或 `/ajax/`），也不觸發重試；失敗後的 fallback 鏈與預設相同 |
| `0` | 模式 0 先；沒有結果時 `searchContent` 把 `搜索模式` 永久改成 `1`、`搜索模式0` 暫設 `0`，重試一次模式 1 |
| `搜索模式0` | 不是給站台設的開關，而是 `searchContent` 重試時暫設的內部旗標：`0` 時 `Z()` 跳過模式 0（JSON），xml 仍會試。設定檔沒有任何站使用 |

所以設定裡的 28 個 `搜索模式=1`，有 27 站和沒設完全相同；色花堂的 `1` 讓 HTML 先走（iOS 現在就是這樣），`搜索后缀` 只在模式 0 組連結時才用得到。

和 iOS `XBPQ.js` 的 `searchContent` 對照：iOS 只做「含 `{wd}` 的網址＋單頁＋有／無 `搜索数组`」，也就是模式 1 的單頁版；沒有片名過濾、`{pg}` 連抓多頁、`搜索前`＋關鍵字＋`搜索后`、POST、`<form>` 自動偵測、模式 0、xml、`特殊分类`、首頁／分類 fallback。

### 7.5 S5-3 收益估計

- **連同原版整條 fallback 一起移植**：A 類 0 站，所以也是 **0 站**。實測 suggest 有回 JSON 的：SEAJAV、天美（已是 E）、18j、最爱扒裤衩、歐視（B，卡在播放或詳情，搜得到也播不了）、天天／天天動漫（C，詳情頁同樣是 Security Check）、KISSAV×3（0 筆）。rss 有 `<item>` 的只有最爱扒裤衩（B）。D 類 6 站 suggest 與 rss 全部失敗。
- **建議：不做 S5-3**，也不做第 4 項。

### 7.6 不應做的 fallback 與原因

- **整條 fallback 鏈**：每一步都是額外請求，還有 1 秒 `sleep`；分類逐一試，N 個分類的站最多 N 次請求加 N 秒。App 的搜尋是全站台同時查、30 秒期限（IOS-POC-20），會拖慢所有站的搜尋，而這批沒有一站因此受益。
- **自動打 `/index.php/ajax/suggest`**：回應只有 id，詳情連結要靠推出來的前綴（上一節中可信的部分），而且 `limit=500` 會回大量結果。
- **首頁／分類頁篩片名**（第 4 項）：只找得到瀏覽第一頁本來就看得到的片。
- **`<form>` 自動偵測**：亚瑟影库實測會組出 404 的 `/s/{wd}/`。
- **片名過濾**：魔法少女2 的片名被規則寫死，照搬後會從 20 筆變 0 筆；文件夹 22 筆會剩 3 筆。iOS 目前不過濾是刻意保留的差異。
- **`searchContent` 把 `搜索模式` 永久改成 `1` 的副作用**：會讓同一個 session 後面的搜尋行為和第一次不同，不要移植。

### 7.8 使用者可以在設定檔修的搜尋（不改程式；App 未驗證）
